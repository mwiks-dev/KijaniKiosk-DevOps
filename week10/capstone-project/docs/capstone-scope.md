# Capstone Scope Document

## Problem Statement

KijaniKiosk currently processes receipt events through an asynchronous serverless workflow consisting of three AWS Lambda functions. While the workflow successfully validates, processes, and notifies users about receipts, it does not provide downstream aggregation or analytics of receipt data. This limits the organization's ability to generate operational insights from processed receipts. The capstone project addresses this gap by extending the existing event-driven architecture with an analytics service and implementing a controlled CI/CD deployment pipeline for staging and production environments.

## Track

Cloud Computing – Serverless Applications, Kubernetes Integration, and CI/CD Automation

## What I Will Build

The capstone project will extend the existing KijaniKiosk receipt-processing system by implementing the following components:

1. **kk-analytics Lambda Function**

   * Develop a fourth AWS Lambda function that consumes receipt events from the existing workflow.
   * Aggregate processed receipt data into structured analytics summaries.

2. **Event-Driven Analytics Integration**

   * Configure **kk-notifier** to trigger **kk-analytics** after notification processing.
   * Ensure analytics are generated automatically whenever a receipt is successfully processed.

3. **Staging Deployment**

   * Deploy the complete four-function serverless application and supporting AWS resources using:

     ```bash
     serverless deploy --stage staging
     ```

4. **Kubernetes-to-Serverless Integration**

   * Configure the Kubernetes **kk-payments** service to publish receipt events to the appropriate staging and production S3 buckets.
   * Ensure receipt uploads correctly initiate the serverless processing pipeline.

5. **CI/CD Promotion Pipeline**

   * Configure Jenkins to:

     * Automatically deploy to the staging environment.
     * Execute integration tests.
     * Require explicit human approval before deploying to production.

## What Is Out of Scope

The following capabilities are intentionally excluded from this capstone project:

* Multi-region deployment
* Integration with a real third-party payment provider
* Enterprise data warehouse implementation
* Full business intelligence or dashboard platform
* Autonomous AI deployment and analytics
* Enterprise disaster recovery architecture

## Success Criteria

The project will be considered successful if the following criteria are met:

### Criterion 1

The command:

```bash
serverless deploy --stage staging
```

successfully deploys the complete four-function serverless stack together with all required event resources.

### Criterion 2

A receipt generated by **kk-payments** successfully travels through the complete serverless workflow and produces an analytics summary containing:

* Receipt count
* Total receipt amount
* First receipt timestamp
* Last receipt timestamp

### Criterion 3

The Jenkins CI/CD pipeline enforces controlled production promotion by requiring the following sequence:

```
Staging Deployment
        ↓
Integration Tests
        ↓
PASS
        ↓
Human Approval
        ↓
Production Deployment
```
